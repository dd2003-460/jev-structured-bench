# 公开模型成绩 × 本地实测 · 同 bench 对比（2026-10-25）

> 核心问题：网络上各种模型（Jev、开源决策模型、同代基础模型）在这些 bench 上什么成绩？和我们本地零训练的 Qwen3.8-27B 比怎么样？
>
> **第一纪律：口径不可混比。** 本文所有数字按三种口径分层标注，跨口径比较只用于"量级感知"，不用于结论。

---

## 口径分层（先读这个，再看表）

| 口径 | 怎么跑 | 谁在用 | 特性 |
|---|---|---|---|
| **L = 对数概率** | 一次前向，取各选项 next-token logprob 的 argmax，不生成任何文本 | JEV 论文的 Qwen 参照、llama.cpp 榜单、so1 外包装、Nimble/Kev/JEB/Jeeves/Clef 全部后训练模型 | 上限口径：不需要解析、无格式噪声；对 MMLU 这类知识题通常最高 |
| **G = 生成** | chat/completions temperature 0，让模型吐出选项字母再解析 | 我们的 harness、Cerebellum 等社区部署评测 | 部署口径：agent 真拿到就是这样；受格式/解析影响 |
| **S = 自建 held-out** | 作者私有测试集（如 Nimble 324 题） | Bespoke-Nimble、Kev、AutoTrust 系 | 只在该集内部可比；作者自选切片，需打折扣看 |

## 表 1（最重要）：同一个 Qwen3.8-27B，两种口径差多少

论文（arXiv:2609.37647 Table 3，§3.6）用 **L 口径**（A100 80GB bf16、thinking off、选项代码 A/B/AA…单 token 化）跑 Qwen3.8-27B；我们用 **G 口径**（4×V100 W8A16 180W、temperature 0、结构化强制工具调用）跑同一个 base 模型：

| 数据集 | 论文 L 口径（n=全量） | 我们 G 口径（n=子样本） | Δ（我们−论文） |

| ARC (E+C 合并) | **98.0** | 95.0（n=60，仅 Challenge） | −3.0 |
| HellaSwag | **94.9** | **86.7**（n=60，干净重跑） | **−8.2** |
| SST-2 | 95.4 | 98.3（n=60） | +2.9 |
| AG News | **86.7** | 78.3（n=60） | **−8.4** |
| Banking77 | **77.4**（n≈3,080） | 80.0（n=60，锁温） | +2.6 |
| IMDB | 论文未列（Jev 95+ 量级） | **91.7**（n=60，干净重跑） | — |
| TruthfulQA | 论文未列 | 78.3（n=60，干净重跑） | — |
| MathQA | 论文未列（Jev 比前沿中位数低 17.7pp 的软肋项） | **50.0**（n=60，干净重跑，全表最低） | — |
| WinoGrande | 76.3 | — | — |

> **干净重跑说明**：HellaSwag/TruthfulQA/IMDB/MathQA 四个新集首跑（经本地代理）报的 85.0/71.7/78.3/48.3 混入了 18 个 HTTP 502 传输错误（被误记成"解析失败"）；直连+重试的干净重跑为 **86.7/78.3/91.7/50.0**，解析失败归零。上表用干净数。

**怎么读这张表**：

1. **MMLU −13pp 和 AG News −8.4pp 是口径差为主，不是模型差**。L 口径把概率直接压在正确选项上兑现；G 口径要模型先"决定吐哪个字母"，知识优势在生成端被稀释。三个变量混在一起：口径（主）+ W8A16 vs bf16 量化 + 150 题子样本波动（±5pp @1σ）。
2. **SST-2/Banking77 我们反超**——样本小（60 题）+ 我们锁温 + 动态 enum 经 chat template 进 prompt（双重编码），生成口径在这类任务上不吃亏。
3. **论文的 L 口径 Qwen 数字本身就是强基线**：Banking77 77.4 已经逼近 Jev 的 79.7。也就是说"同代 27B 零训练"在 logprob 口径下离 Jev 只差 2-3pp；差距主要被 Jev 在知识/推理类拉开（MMLU 91.8 vs 81.7、WinoGrande 91.4 vs 76.3）。

**注 1（口径警告）**：Clef 的 Banking77 94.2 是 **macro-F1**，Jev 的 79.7 和我们的 76.7 是 **accuracy**——两者不可直接比（77 类 macro-F1 对类别不均衡极敏感）。
**注 2**：除 so1 的社区 bench 和 riderless 的 suites 外，**全部为项目自报**；Jev/Kev 的 JevBench 数字还限公开层（sealed judge tier 不包含）。

**家族结论**：后训练决策模型的共同发现是"**2676 条针对性样本 ≈ 参数量 9B→27B**"（Nimble 90.12 vs base 27B 84.88，+5.25pp）——微调教的是"怎么用已有能力做决策"，不是新知识（Kev 的学习率实验：LR 2e-4 会灾难性遗忘基座知识，5e-5 才保住；JEB 的 round 1 也实测 MMLU −11，round 2 加知识行才补回）。**知识题（MMLU）是 9B 底座的硬上限**：Jeeves 0.793、Kev-9B 0.74 都低于 Jev 0.90，而分类/意图题上小底座就能追平（JEB-4B 的 AG News/SST-2/TREC 全部 ≥ Jev）。

## 表 4：类似"外包装"实现（零训练 / 推理期约束）——与我们本地路线同宗

这一类不改权重，只在推理期把决策从"生成"改成"读概率"。RedLineSoft 博客把开源复刻归纳为三条技术路线，**其中 Approach 1 就是我们本地 C4 第一念实验 + Path A 的产品化**：

| 路线 | 代表 | 成绩（自报/第三方） | 延迟 | 硬件 |
|---|---|---|---|---|
| **① Prompt-Logprob 外包装**（无训练，一次前向读选项分布） | **so1 / open-alternative-jev**（ikermoel，Python 库，HF+vLLM） | **同一第三方 scorer 正面对决**：LocalLLaMA/typed-decisions 400 cases/2000 decisions，Qwen3.6-27B 8-bit **73.7%**、ECE 0.020、582ms vs **Jev 72.7%**、ECE 0.144、710ms；RACE-H 92.9%（packing 4.55 q/s）；MMLU 1200 题 **84.2–84.9%** | 582ms/case（H200 MIG） | 标准 LLM GPU |
| ① 同族 | ekzhang/openjev-sglang、bnsd55/openjev、riderless（Gemma 零生成） | riderless 自建 suites 同 scorer：so1 0.921(独立)/0.901(packed)、Kev-9B 0.898、Laya 0.618 | ~150–250ms | 同上 |
| **② 小模型 + 打分头**（微调，边缘向） | system-one-gemma（Gemma 3 270M+2.6M LoRA）、openJev-verdict-2.0（ModernBERT 151M） | 64.4% / 77% | 15–50ms（CPU/WebGPU） | 任意硬件 |
| **③ 离散扩散读概率**（无训练） | DiffusionGemma 26B-A4B | — | 94ms/3 题，57 req/s @64 并发 | ≥24GB VRAM |

**so1 的 README 有一条值得学的诚实更正**：初版报"比批处理快 1.4 倍"，回归分析发现 B/C 两种模式每 token 耗时完全一样（0.96 vs 0.97 ms），差异全来自批处理的 padding 浪费——作者把错误分析和原始数据一起留在仓库里。这和我们 benchmark 连抓 6 个 harness bug 是同一个纪律：**先证明测量工具没问题，再谈模型结论**。

**这张表是全文信息量最大的一张**，三个读数：

## 综合结论（2026-10-26 补全后）

1. **同 base 模型（Qwen3.8-27B）零训练，L 口径已经很强**：Banking77 77.4 / SST-2 95.4 / ARC 98.0 / MMLU 81.7——Jev 的优势集中在知识/推理密集型（MMLU −10.1、WinoGrande −15.1），在情感/意图分类上只差 1-2pp。
2. **我们的 G 口径 vs 论文 L 口径**：分类任务（SST-2/Banking77）打平或反超，知识/主题/常识任务（MMLU −13、AG News −8.4、HellaSwag −8.2）落后——差距主因是口径（生成字母 vs logprob argmax）而非硬件/量化，但 W8A16+180W 的贡献未被单独隔离，属未决变量。**9 数据集 630 题总 accurate 78.7%，最低项 mathqa 50.0%**（多步计算，与 Jev 论文"计算类是软肋"同向）。
3. **三条路线的定价（回答"该买什么/该做什么"）**：
   - **外包装（零训练，读 prefill 概率）**：同一底座不改权重，MMLU +2.5~3.2pp（so1 84.2 vs base L 81.7），分类任务打平 Jev，延迟 150–580ms。**分类/路由/审核场景，外包装就是性价比终点**——我们本地 C4 第一念实验已独立验证同一机制（banking77 第一念 86.7% 反超 JSON 路线 73.3%）。
   - **后训练（LoRA+指针头/读出头）**：买的是知识题（MMLU 84→91.8）+ 校准（ECE 0.025）+ 延迟（70–500ms）。知识题的增益来自底座参数量，9B 封顶 ~0.79（Jeeves/Kev 实测），27B 底座才够到 0.90。
   - **Jev 官方**：为"知识判定 + 敢拒答的校准概率"付费，不为分类付费。且 JevBench 上已被开源的 Jeeves 超过（0.935 vs 0.866）。
4. **"开思考"的结论要修正边界**（我们本地 vs Jeeves 官方对照实验）：我们本地临场 prompt CoT 85.0%→81.7%（有害），**但 Jeeves 的同一检查点训练出来的思考链 0.804→0.840（有益，+3.6pp）**——差别在思考是**训练过的**还是**临场 prompt 的**。正确表述：**选择题上，未经训练的临场 CoT 有害；训练过的思考（SFT+RL 教模型什么时候想、想什么）有益但慢 10 倍**（0.3s→3.3s 中位，p90 17.1s）。我们本地的 C1/C3 结论只覆盖前者。
5. **后训练决策模型的增益真实存在但集中在自建集**：Nimble 用 2,676 样本把 9B 从 66.4 拉到 90.1（自建 324 题）；JEB 是第一个在公开标准集上直接列 Jev 对照的（4,177 题总 0.836 vs 0.897）。但没有任何一家在标准 bench 上全面超过 base 模型的 L 口径——**"后训练 vs 零训练结构化输出"在标准 bench 上的正面对决仍不完整**，JEB/Jeeves 补上了第一块砖。
6. **Jev 的真正护城河是校准而非准确率**：ECE 0.025 vs Qwen 0.045，且概率支持选择性拒答。但 so1 用零训练外包装在同一 scorer 下拿到 ECE 0.020（Jev 0.144 在同 bench）——**校准也没那么难复制，Jev 的 0.144 是在 typed-decisions 这个分布外 bench 上掉的**。我们本地任何机制（结构化/自由文本）产出的 confidence 都只是自称值，第一念的选项分布（C4）是唯一有概率意义的信号。
7. **给我们的定位**：本地 9 数据集 78.7%（G 口径）+ 第一念实验 + 630 题可复现 harness，放在公开谱系里是"外包装路线在消费级硬件（4×V100 180W vs H200）上的完整实证"——包括它在哪里有效（分类）、在哪里吃亏（知识题 MMLU −15.5pp vs so1）、在哪里反超（banking77 第一念 +13.4pp vs JSON 脚手架）。**这些正是 so1/JEB 都没做的：同一模型上 G 口径 vs L 口径 vs 外包装的三方对照。**
